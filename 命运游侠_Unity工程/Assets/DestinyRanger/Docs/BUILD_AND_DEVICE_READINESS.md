# 命运游侠 v0.1 构建与设备清单

## 当前构建目标

- Unity：`2022.3.62f3c1`
- 设计设备：iPad / 平板横屏
- 设计分辨率：`2732 × 2048`
- 运行方向：横屏，禁用竖屏自动旋转
- 全屏：iOS `requiresFullScreen` 开启，状态栏隐藏
- Bundle Version：`0.1.0`
- Bundle Identifier：`com.destinyranger.prototype`
- 目标帧率：流畅档 60 FPS，省电档 30 FPS
- 安全区：HUD、左摇杆和右侧战斗按钮挂在 `SafeAreaRoot` 下，运行时跟随 `Screen.safeArea`
- 设置确认：设置页顶部 `SettingsComfortBadges` 显示标准/低闪、自动/手动朝向、右手按钮状态、控制器连接状态、离线单机和无广告/无分析徽章
- 前景可读性：世界层必须存在 `ForegroundReadabilitySoftEllipse_NoPlate`、透明禁用的 `HeroContrastSilhouette`、`HeroReadabilityAura_DisabledNoGroundBlob`、`HeroLandingPredictor` 和透明禁用的 `EnemyContactAo_DisabledNoGroundBlob`，避免森林背景、平台边缘和技能特效吃掉角色/敌人轮廓；角色/怪物脚下不得靠黑影、蓝光环或脚底贴图块读清，空中落点才使用预测线。
- 相机构图：`ComputeCameraLookAhead` 必须根据横向输入和 `facing` 平滑调整 `cameraLookAheadX`；向右推进时看得更远，回头/后撤时柔和回收，接近房间右边界时降低前视，不能固定只向右偏移。疾跑期间由 `TrackQuickRunRoomUsage` 点亮 `quickRunCameraTimer`，并额外增加约 `.42f` 的前方视野，让满推/双击快跑时能提前看到平台和敌人，但仍受房间右边界收束限制。战斗中必须调用 `TryGetCombatCameraThreat`，按 Boss、精英、弓手、近身敌人优先级选择当前房威胁，并通过 `CameraThreatFocusBlend` / `CameraThreatVerticalBlend` 将镜头轻微混合到主角和威胁之间，让敌人前摇、平台落点和右手按钮区同时可读，不能突然甩镜头或把玩家长期压在边缘。
- 危险区可读性：Boss 砸地/激光、敌人近战、弓手瞄准、雷阵和毒素光环必须通过 `AddDangerPattern` 添加斜纹、十字准星或波纹线，并通过 `AddDangerPatternGlyph` 添加 `DangerPatternDamageGlyph`、`DangerPatternCrosshairGlyph` 或 `DangerPatternToxicGlyph`，不能只靠红/绿颜色表达危险类型；普通近战/弓手预警必须用 `ArcherAimThinWarnLine`、`ArcherAimEdgeTick_NoYellowPlate`、`ArcherAimTipNoPlateTick`、`EnemyMeleeThinGroundWarn`、`EnemyMeleeFrontEdgeWarn_NoYellowPlate` 这类细线和刻度，且不能触发中央威胁底板；Boss 前摇必须用 `BossAttackReadabilityNeedleLine_NoTexturePlate` / `BossAttackReadabilityFootLine_NoTexturePlate` 和短词，倒计时只能用 `BossNoPlateLine` / `BossNoPlateTick` / `BossNoPlateNumber`，不能回退到两行世界文字；Boss 雷阵必须用 `BossThunderThinCrosshairWarn` 和 `BossThunderLandingEdgeTick`，弓手末端刻度、雷阵落点、毒圈边缘和倒下来源标记都必须是低透明细线，禁止在运动或敌人攻击时出现黄色填充背景板、黄色推进箭头或黄色锁门脉冲。
- 方向可读性：HUD 必须存在 `TargetCompassText` / `TargetCompassBackplate`，在当前房间有敌人、`SLOT` 宝箱或平台小宝箱时显示方向、屏外/左侧/右侧/上方状态和距离。
- 复玩入口：标题页包含普通试炼、今日试炼和试炼热度 H0-H3
- 标题页模式说明：`TitleModeGuideText` 必须根据辅助模式、热度、今日试炼和本地成就状态给一条短推荐，并明确今日试炼只保存本机最佳、热度不改变 SLOT 概率。
- 本地成就：成就页显示本地解锁进度和“推荐追踪”目标，不接账号、联网排行或 Game Center
- 资产来源：正式图片登记在 `Assets/DestinyRanger/Docs/ASSET_PROVENANCE.md`，均来自项目生成资产目录 `Assets/DestinyRanger/Art/Generated`
- 主角动作规格：`Assets/DestinyRanger/Docs/HERO_ANIMATION_SPEC.md`
- 触控布局规格：`Assets/DestinyRanger/Docs/TOUCH_CONTROL_SPEC.md`
- 打击反馈规格：`Assets/DestinyRanger/Docs/FEEDBACK_SPEC.md`
- 首局体验规格：`Assets/DestinyRanger/Docs/FIRST_RUN_SPEC.md`
- 上架元数据规格：`Assets/DestinyRanger/Docs/RELEASE_METADATA_SPEC.md`
- 本地存档规格：`Assets/DestinyRanger/Docs/LOCAL_SAVE_SPEC.md`
- 手柄兼容：蓝牙/MFi 控制器默认可用左摇杆移动，`A/B/X/Y` 分别映射跳跃、闪避、攻击和当前核心技能；`L1/R1/L2` 作为未来技能扩展预留，不在 v0.1 战斗 HUD 常驻显示；实际按钮受系统重映射影响，战斗 UI 不硬显示手柄 glyph，设置页通过 `HasConnectedController` 显示连接状态，屏幕按钮会同步显示手柄按下态

## 人工检查

- iPad 横屏下标题页、关于/隐私、设置页、符文启封、商店和结算弹窗均不被安全区遮挡。
- `ValidateNoThirdPartySdkBatch` 通过：无广告、分析、IAP、第三方统计 SDK 或联网 API，`submitAnalytics: 0`。
- 右手按钮贴右但完整留在安全区内，不进入系统手势边缘；默认布局必须是攻击键最大、跳跃/闪避贴近攻击键左上侧，正式触控 HUD 只显示一个核心技能：`Skill1` 剑气，隐藏 `Skill2` / `Skill3` / `Skill4` 避免右手区和技能特效过载；隐藏技能只能保留为内部扩展，不得绑定触摸反馈、技能预览、拖动微调或正式布局坐标。`RuneOpen` 位于单技能上方偏内侧作为 SLOT/宝箱入口，不压攻击/跳跃/闪避。标准布局坐标必须保持 `Attack (-36,188)`、`Jump (-226,218)`、`Dodge (-178,356)`、`Skill1 (-100,462)`、`RuneOpen (-198,536)` 这一组基准；紧凑布局保持 `Attack (-34,178)`、`Jump (-218,202)`、`Dodge (-170,332)`、`Skill1 (-96,438)`、`RuneOpen (-190,512)` 的右侧五键区。右手位置档位不能把整组按钮等量右推导致跳跃键压到攻击键下方，必须通过 `ControlReachOffsetForButton` 和 `BossFocusButtonOffset` 按按钮类别缩放偏移；单键拖动微调仍经过 `ClampCombatControlPosition`，最小热区不低于 `CombatControlMinTouchSize`，攻击键必须完整显示不裁切。
- Boss 战必须通过 `BossRightHandUiAvoidanceActive` / `BossRightHandUiSafeLookAhead` 给右下按钮区留出镜头安全量；威胁聚焦之后还必须追加 `BossRightHandUiFinalCameraShift` 的最终右移修正，正式 Boss 默认站位约 `44.6f`，预览 Boss 也使用约 `44.6f`，避免 Boss 贴在最右边被攻击键、单技能或 `SLOT`/补给键压住。Boss、本体前摇、地面危险范围和小宝箱不能被攻击键、单技能或 `SLOT`/补给键压住。
- 触控预输入：攻击、跳跃和闪避预输入逻辑保留，但正式 HUD 隐藏攻击、跳跃和闪避预输入微文案；动作触发、窗口结束或打开面板后内部提示清空。攻击缓存消费必须生成 `AttackBufferConsumedTick` / `AttackBufferConsumedRing`，tick 约 `88x7`、alpha `.44`，ring 约 `196x196`、alpha `.070`；闪避缓存消费必须生成 `DodgeBufferConsumedTick` / `DodgeBufferConsumedRing` / `DodgeBufferConsumedFootLine`，tick 约 `78x8`、alpha `.50`，ring 约 `164x164`、alpha `.080`。
- 变量跳跃：跳跃键 PointerDown 必须立即起跳，短按触发 `CutJumpHeight` 并低跳，长按达到完整跳高；疾跑状态下地面起跳要调用 `StartQuickRunJumpCarry`，只在空中前约 `.34s` 且同方向输入仍高于 `.20` 时保留一点疾跑横向惯性，松开、下拉或反向都会快速衰减，落地后 `ContinueQuickRunAfterLanding` 只允许续约 `.28s` 同向快跑窗口，不能穿过推进锁、平台边缘、旧门框或变成自动滑翔/落地冲刺；离地后允许一次 `MaxAirJumps` 二段跳修正高台/断桥落点，`SpawnAirJumpFeedback` 只能生成小型青白 `AirJumpCrispRing` / `AirJumpLiftTick`，且 `AirJumpCrispRing` 必须是 `CombatVfxSprite(0)` 细线；疾跑起跳和落地续跑只允许 `QuickRunJumpCarryFootLine_NoYellowPlate` / `QuickRunJumpCarryLiftTick_NoYellowPlate` / `QuickRunLandingCarryFootLine_NoYellowPlate` / `QuickRunLandingCarryForwardTick_NoYellowPlate` 短反馈，`SpawnJumpCutFeedback` 只能生成 `JumpCutDustCleanLine`，不得生成大残影、软圆或黄色背景板；空中普通攻击必须通过 `ApplyAirAttackStabilizer` 做小幅 `AirAttackLightDrift` / `AirAttackHeavyDrift` 前移和 `AirAttackFallBrakeVelocity` 下坠刹车，只生成 `AirAttackStabilizeLine` / `AirAttackFallBrakeTick` 短线，不能无限浮空、穿过推进锁或复制主角残影；暂停、切后台、重开或 PointerExit 后 `touchJumpHeld`、`quickRunAirCarryTimer` 和落地续跑窗口不得残留。
- 平台边缘宽容：`ReadKeyboardAndMove` 必须使用 `PlatformLandingEdgeAssistX`、`PlatformLandingEdgeSnapInset` 和 `PlatformLandingStableEdgeTolerance` 做只在下落穿越平台顶面时生效的落地吸附；玩家脚点接近平台左右边缘且横向输入指向平台内侧时可轻微吸入平台，并落在稳定支撑判断不会排除的位置，避免差一点点掉落或边缘卡死。普通走跳仍保持 `.020f` 基础宽容，只有 `quickRunAirCarry` 为真时才叠加 `QuickRunLandingEdgeAssistBonus = .070f`；该加成仍要求 `crossingTop`，不能从侧面/下方吸上平台，也不能改变推进锁。吸附成功只显示极短的 `PlatformLandingEdgeAssistPin_NoYellowPlate`，禁止再出现长横向脚下线。
- 平台下穿：站在非地面平台时按“下方向 + 跳跃”必须调用 `DropThroughPlatform`，设置 `PlatformDropThroughDuration` 和 `platformDropThroughTarget`，仅临时忽略当前平台；下穿不能穿过地面、Boss 锁场或房间推进边界，打开弹窗、暂停、重开和回标题时必须通过 `ClearPlatformDropThrough` 清空残留。反馈只允许 `PlatformDropThroughFootLine_NoYellowPlate` / `PlatformDropThroughDownTick_NoYellowPlate`，不能显示大箭头、黄色板或世界文字。
- 厚地板和平台美术不能把玩家脚点夹住：`NormalizePlayerSupport` 必须在移动帧和异常输入锁恢复后执行，使用 `PlatformSupportUnstickTolerance` 把轻微陷入平台顶面的角色顶回可站面，并保持 `StableSupportYAtX` 不吸附头顶平台；站在平台左右边缘持续往外走时，`ApplyPlatformEdgeHorizontalEscape` 必须按输入方向给 `PlatformEdgeHorizontalEscapeNudge` 的当帧边缘释放，并只在这个离开动作里额外使用 `PlatformEdgeEscapeSupportToleranceBonus = .055f` 找回当前支撑，让玩家自然走下平台，不能被平台支撑 inset 或厚平台贴图黏住；`RecoverPlayerIfMovementStuck` 必须通过 `TryFindMovementStuckRecovery` 多点探测输入方向上的同层或更低稳定支撑，约 `.018s` 内介入，先用 `TryRecoverOffPlatformEdge` 和 `PlatformEdgeStuckRecoveryOutset = .24f` 释放平台边缘卡点，再用 `MovementStuckRecoverNudge` 约 `.40f`、`MovementStuckRecoverProbeCount` 约 `10` 做常规探测，只有超过 `MovementStuckRecoverMinAdvance` 才修正位置；防卡探测可额外使用 `MovementStuckSupportCeilingBonus = .055f` 的极小厚地板容错，但静态上限必须保持 `MAX_MOVEMENT_STUCK_SUPPORT_CEILING_BONUS = 0.065`，避免吸到头顶平台。这样能减少角色有跑步动作但坐标出不去；如果当前没有真实锁门，`ReadKeyboardAndMove` 必须在门边附近调用 `ApplyGateEdgeSoftReleaseNudge` 给持续向右输入一个极短当帧推进，并调用 `ApplyOpenRouteIntentUnstickNudge` 使用 `OpenRouteIntentSoftNudge` 做开放路线即时软脱困，再由 `OpenRouteStuckRecoveryRight` 临时扩展开放路线探测范围，且 `recoverableOpenRouteRightLimit` 不能被提前返回吞掉，不能被旧门框、旧 segment 或视觉厚地板夹在原地；`AuditMovementUnstuckBatch` 必须包含 `platform-unstick-*`、`platform-leave-*`、`visual-ground-pocket-recover`、`open-route-stuck-widen`、`open-route-right-intent-*`、`open-route-intent-soft-nudge` 和 `gate-edge-soft-release` 样例，确认每个平台顶面下陷状态、平台边缘离开、视觉厚地板卡点和开放路线旧边界都会恢复。
