# 命运游侠 v0.1 市场对标记录

## 对标来源

- Soul Knight: [Google Play](https://play.google.com/store/apps/details?id=com.ChillyRoom.DungeonShooter) 页面强调 easy and intuitive control、roguelike elements、random dungeons、auto-aim mechanism、dodge/fire/cast skill with a few taps。
- Dead Cells Mobile: [App Store](https://apps.apple.com/us/app/dead-cells/id1389752090) 页面强调 2D action、rogue-lite replayability、mobile redesigned interface、Original & Auto-Hit modes、custom touch controls and swipe to dodge。
- Dead Cells: [官方更新记录](https://dead-cells.com/patchnotes#mobile) 里持续补控制图标、文本背景、地图图标和 Auto-hit 等可读性/QoL 项，适合作为高速战斗中 HUD 文案、按钮状态和 Boss 提示的可读性基准。
- Hades: [Supergiant Games](https://www.supergiantgames.com/games/hades/) 页面强调每次逃脱尝试都会通过不同神力组合改变战斗方式，适合作为“本局构筑回顾”的参考。
- Apple Human Interface Guidelines: [Game controls](https://developer.apple.com/design/human-interface-guidelines/game-controls) 强调 iPhone/iPad 游戏需要支持触控默认交互、按钮要有手指遮挡下仍可见的按下/发光状态，并结合声音/触觉反馈；[Designing for games](https://developer.apple.com/design/human-interface-guidelines/designing-for-games/) 强调触屏尺寸、菜单可读性、不同宽高比和安全区适配。

## 已转化到当前原型的设计约束

- 移动端优先：右下大攻击键、跳跃/闪避贴近右拇指区，v0.1 只保留一个可见核心技能和一个 `SLOT`/补给交互键，左下摇杆负责移动。
- 右手热区：默认战斗按钮整体更贴近右边缘，攻击键最大且最低，跳跃/闪避在攻击键左上侧，单个核心技能和 `SLOT`/启封键在上方偏内侧分层摆放，再通过设置里的右手位置档位和单键拖动微调适配不同握持。
- 左手移动热区：左摇杆不能要求玩家精准按中小圆盘，底部左侧需要较大的隐形触控区；按下后底盘跟随拇指位置、摇杆头和透明度明确表达方向/强度，松手回默认位；横向移动、上推跳跃和横滑闪避需要意图锁，减少斜向输入误触。
- 移动端标签：主屏幕按钮使用攻击、跳跃、闪避、技能名和上下文交互等动作语义，不显示键盘字母；键盘映射只放在暂停说明，避免首屏像调试界面。
- 按钮可读性：右手技能和核心交互必须有独立 `ReadyGlow` 可释放外圈高亮，以及不可用灰化/冷却遮罩两层反馈，玩家不能只靠小字判断按钮状态。
- 技能资源可读性：战斗中不常驻显示消耗，避免技能簇塞满小字；资源不足时只用中心 `MP`、红暗遮罩和标签降透明共同表达不可用原因，不再叠顶部“缺MP”短 token，避免玩家误以为按钮坏了或输入无响应。
- 自动瞄准可读性：自动朝向/自动攻击不能只悄悄改角色朝向，必须在当前目标附近显示低透明短准星；战斗中优先不用目标文字，避免小怪头顶和攻击特效堆叠。
- 新手引导：首次开始前用可跳过简报解释“战斗-奖励-SLOT-商店”核心循环，世界内第一屏只显示触屏动作语义和手势意图，不把键盘测试映射当作正式教程。
- 安全区适配：HUD 和触控按钮必须跟随设备 `safeArea`，避开圆角、刘海和系统手势区，减少 iPad/平板横屏设备差异带来的误触。
- 流畅度底线：移动端动作游戏需要显式帧率目标和稳定固定步长，默认 60 FPS 流畅档，同时提供 30 FPS 省电档，避免默认帧率策略导致触控响应、动画帧、命中停顿和发热表现不可控。
- 角色动作权重：主角动作不只换帧，还要有起跳拉伸、落地压缩、跑步脚步节奏、闪避横向拉伸、命中帧身体前压和重击压缩释放，让触屏短操作也有明确身体反馈。
- 低血可读性：低血不能只靠红边，要给非阻塞战术提示，告诉玩家该回血、拉开距离、等闪避冷却或利用防御/控制构筑。
- 降低触控瞄准压力：默认开启自动朝向，攻击和技能会先面向最近敌人；设置页另提供默认关闭的自动攻击，参考移动动作游戏的 Auto-hit 辅助，但只在近身敌人或符文罐进入范围时出刀，避免替玩家乱触发交互。
- 长按操作：攻击按钮支持点按和长按连续攻击，减少平板上反复点按的疲劳；攻击、跳跃和闪避都需要短输入缓冲，跳跃还需要短离地宽容，降低触屏误差导致的空输入；摇杆上方向只在首次推到阈值时触发跳跃，避免按住摇杆造成自动连跳。
- 预输入可见化：移动端动作游戏不能只在内部吃输入，但正式 HUD 不应堆小字；攻击、跳跃、闪避的缓冲窗口用按钮短促回弹、连击点、冷却数字和角色动作确认，避免在右手区常驻“缓存/预闪/二跳”等微文案。
- Swipe 闪避：左摇杆横向短划触发闪避，同时保留独立闪避键。
- 极限闪避：参考高速移动动作游戏的擦弹/精准回避反馈，闪避窗口内避开攻击会给短暂停顿、蓝白确认和少量命运能量奖励，强化“会躲也能更快启封 SLOT”的技术收益。
- Roguelite 短循环：击败敌人积累命运能量，满 100% 刷奖励 SLOT；清关、精英、商店、罐子也能触发启封；HUD 需要用 `NextSlotHintText` 显示 `启封 / 商店100 / 差X金 / 临界XX% / 差X%` 这类短状态，提示平台罐、极限闪避和商店来源，让玩家知道下一次构筑变化从哪里来。
- 抽奖结果可读性：`SLOT` 停止后必须明确显示三星/二星/保底，不只展示三个图标；结果文案要直接说明“核心流派成型、战斗能力强化、保底回血”这类战斗意义。
- 构筑变化反馈：参考 Hades/Dead Cells/Vampire Survivors 等短局构筑游戏，奖励结果需要直接显示本次构筑前后变化和当前战术用途；本项目的 `RuneBuildDeltaText` 必须在启封后显示符文等级变化、总构筑等级变化或补给/回血保底。
- 平台合规包装：SLOT 只作为战斗内符文表现，不接真钱付费、不承诺现金价值；若未来接入任何 IAP 随机虚拟物品，必须在购买前披露概率并重新审查平台政策。
- 概率透明：即使当前 SLOT 不含 IAP，也要在局内临界/待启封/商店可启封时用 `RuneOddsText` 显示三星、二星和逆运祝福概率，并在符文面板/图鉴重复同一口径，避免随机奖励信息只藏在说明页。
- 内容分级包装：战斗按幻想/卡通动作处理，敌人受击用闪白、击退和消散表达；不出现血腥、肢解、真实武器教学、下注、赔付、现金兑换或真钱博彩。
- 随机遭遇：多个推进点不再固定刷同一只怪，而是在近战、远程、史莱姆组合中抽取，提升重开差异。
- 房间词缀：普通战斗房随机出现疾行、强袭、命运涌流、罐藏、精准试炼或稳态，让每局清房条件和奖励侧重点变化；其中疾行房会追加限时清房奖励，罐藏房会追加“打破目标符文罐开门”的硬目标，精准试炼房提示极限闪避挑战，接近移动 Roguelite 的轻量 challenge condition。
- 房间节奏：单关拆成 8 个短推进房间，固定放入商店房、精英房和 Boss/终段房，接近移动 Roguelite “清房-奖励-下一房”的可读节奏。
- 房间用途：进入新房要给一次明确提示，商店房必须停留并打开补给，精英房和 Boss 房要用颜色、震屏、HUD 目标、房门状态和特殊房门徽章把危险等级提前告诉玩家。
- 开门反馈：清房后屏障解除必须有短演出、门扇滑开和文字确认，让玩家明确“当前房间完成，可以进入下一房”，避免横版长地图里迷路。
- 奖励选择：关键房间清空后给 3 选 1 即时奖励，不只自动加资源；奖励从随机池抽取并带普通/稀有/史诗倍率，让玩家每几分钟就能做一次构筑取舍，靠近 Hades 式“每局组合改变打法”的核心体验。
- 奖励可读性：奖励卡用稀有度颜色、编号、奖励类型图标、类型标签、稀有度条、数值高亮、构筑/路线提示和当前局势推荐标记说明取舍原因，保证平板横屏下可以快速比较并选择；命运能量奖励必须明确标成 `SLOT` 类型，持续强化战斗到启封的核心循环。
- 清房奖励：每个房间清空后都给金币、治疗、命运能量或奖励 SLOT，把 Soul Knight 式“清房后掉落/宝箱期待”转化为横版推进节奏。
- 商店可读性：商店商品必须用图标、价格、买不起差额、售罄状态、总决策行和购买建议表达决策，低血推荐回血，构筑未成型推荐买 SLOT，Boss 前说明容错或补强收益，金币不足时建议离开后优先清房/平台罐，避免只靠一行按钮文字。
- 掉落吸附反馈：击败敌人和打开平台小宝箱后生成金币、生命、命运碎片拾取物，靠近角色自动吸附；收取瞬间必须有短文字、颜色和音效确认，提升资源获得的即时手感。
- 打击反馈：命中必须同时给停顿、镜头、屏幕闪白、火花、血条脉冲、按钮二次回弹和伤害字弹出/上浮；普通轻击、第三段重击、技能命中要有不同力度，技能弹体要保留 `SourceSkill` 以回弹正确按钮，近战需要区分出刀前摇、命中帧冲击和空挥刀光，接近 Dead Cells / Hades 这类高速动作游戏的即时确认标准。
- 音效分层：普通出刀、轻命中、三连破势、技能释放、Boss 高危、拾取、开门和 SLOT 奖励不能共用一种提示音；需要用 `sfxSlash`、`sfxHit`、`sfxHeavyHit`、`sfxSkillCast`、`sfxBossWarn`、`sfxPickup`、`sfxGateOpen` 和 `sfxRuneReward` 区分强度与事件含义。
- 命中分层：轻击只给短火花、小停顿、敌人轻压缩和受击方向拖尾；第三段重击额外给横向冲击带、地面脉冲、更大伤害字、硬直地面环和“破势硬直”；技能命中额外给术式核心/圆环、硬直地面环和“术式硬直”，确保远景平板画面也能读出攻击类型。
- 动作确认：攻击段数、技能起手、受击和击杀要有各自独立的短反馈；连击需要有独立热度条和等级文案，玩家在平板远景下也能读懂“我按下了什么、打中了什么、节奏是否正在变强、有没有击破”。
- 技能释放确认：参考成熟移动端动作游戏的“按下-起手-释放-命中”反馈链，技能按钮、角色姿态、地面提示和命中点必须分层确认；不能只生成弹体或伤害数字，否则触屏玩家会觉得技能输入飘、延迟或没触发。
- 动作动势：起跳、落地、闪避和攻击前冲需要有地面尘/光痕，避免角色像纸片一样只换帧。
- 击杀确认：敌人死亡要同时给爆点、拾取物和简短收益文字，让玩家理解金币、命运能量和 SLOT 机会从哪里来。
- 角色可见性：主角必须始终压过宠物/拾取物层级，攻击/技能帧结束后回到稳定可见帧；动作表帧率要明确，待机、跑动、跳跃、轻击、重击、技能不能共用同一种节奏。
- 右手按钮区：参考移动动作游戏的拇指热区，攻击键最大并靠近右下，闪避/跳跃贴近攻击键，v0.1 只保留一个技能入口，`SLOT`/补给作为特殊交互放在单技能上方偏内侧；按钮布局要比默认居中更靠右，同时提供单键拖动微调。
- Boss 可读性：Boss 战需要顶部专用血条、短阶段 token、当前招式短提示和颜色变化；二阶段必须有短演出和 HUD 文案确认，但不能常驻攻略长句。保留闪避、收招反击和冰环窗口等信息应通过前摇短词、地面细线、反击窗口和一行短提示表达，避免顶部 HUD 抢走角色、Boss 和平台读图空间。
- Boss 锁场：参考动作 Roguelite 的 Boss 房封闭表现，最终 Boss 存活时需要持续显示锁场边界和地面封锁带，目标栏说明“锁场中”，让玩家知道当前不能继续推进，击破后才进入最终 `SLOT` 和结算收束。
- Boss 阶段标记：Boss 血条要持续显示阶段状态、阶段阈值和无文字压力条，不只在转阶段瞬间弹提示；阶段一显示 `P1 · 50%碎甲`，阶段二显示 `P2 · 雷阵`，避免玩家错过二阶段规则变化，同时保持顶部简洁。
- Boss 收束：Boss 击破、最终奖励和结算之间要有短演出衔接，保证最后一分钟有“打赢了”的明确确认，而不是直接弹面板。
- 敌人意图：近战、远程和 Boss 攻击都要有前摇预警、行动名称/倒计时、危险范围或瞄准线，让移动端玩家能通过走位/闪避处理，而不是事后受击。
- 敌人警戒层：进入攻击距离但尚未真正出招时，脚下需要有蓄力/警戒圈，头顶显示“警戒/瞄准/危险”；蓄力接近高危时额外显示“闪避/拉开”并给屏幕边缘方向提示；真正出招时再显示红区、瞄准线和倒计时，形成“即将攻击”“现在该躲”“马上命中”的三级读法。
- 敌人状态层：冻结、毒素光环、Boss 狂暴等会改变战斗判断的状态必须挂在敌人头顶或血条附近，不能只依赖特效颜色；状态结束后要恢复原本精英/房间词缀染色。
- 可读性优先：角色脚下不能依赖蓝色光环或黑影，顶部目标/事件提示分层加暗底板，低血量有红色压迫反馈，受击要有屏幕边缘方向提示和 `HurtRecoveryText` 短暂恢复窗口提示，让玩家知道伤害来自左/右/上/下哪一侧，以及短暂无敌期应该拉开、补给或反击。
- 失败复盘：死亡页不能只显示“失败”，需要显示倒下房间、推进百分比、最后一击来源和主要受伤来源，帮助玩家形成下一局的明确改进目标。
- 路线可读性：HUD 小地图显示推进段、商店、精英、Boss 与 SLOT 待启封状态，当前房有平台小宝箱时用 `PlatformRouteHintText` 显示左右距离和上推跳跃/攻击开箱操作，减少横版长地图迷路感，并让平台奖励不只像背景装饰。
- 平台路线：平台不能只是背景装饰，至少部分资源罐/SLOT 触点需要放到平台高度，并用世界箭头/光环、目标栏和小地图状态提示“跳上平台”，形成跳跃收益和高低差选择。
- 局后复盘：结算页显示用时、击败数、最佳记录、最高连击、受伤次数、极限闪避次数、SLOT 启封次数、构筑等级、挑战徽章和符文履历；失败页额外显示死亡房间和推进百分比；胜负都要给出“下局挑战”，让玩家理解这一局的流派变化和下一局改进方向。
- 构筑推荐：结算页需要从本局表现反推下一局推荐流派，例如受伤多推荐盾/冰，清场慢推荐剑/雷，远程/Boss 压力大推荐闪避游击，启封少则推荐优先开平台小宝箱和商店 SLOT。
- 今日试炼复盘：今日试炼的结算页要显示是否刷新本机今日最佳，不做排行榜式比较，强调自我挑战。
- 重开目标：局内显示房间进度、试炼等级/经验百分比、时间差和击杀纪录差距，局后明确是否刷新最佳，给短局 Roguelite 更清晰的再挑战理由。试炼等级来自清怪经验，升级只给轻量 HP/MP/攻击成长和短促冷色反馈，不增加左上第四条经验杠。
- 标题页决策：开始前应显示当前推荐路线，帮助玩家区分普通试炼、今日固定种子、H2+ 挑战热度和辅助模式；热度提高难度但不改变 SLOT 概率，今日试炼只保存本机最佳。
- 菜单闭环：标题页展示最佳记录，结算页提供再次挑战和返回标题，并用结算辅助提示说明当前辅助/热度/今日试炼设置如何影响下一局，保证一次完整试玩后能自然重开或调整设置。
- 今日挑战：参考优秀 Roguelite 的每日挑战思路，但 v0.1 只做离线固定日期种子和本机自我最佳，不接账号、不接排行、不发奖励，避免把复玩目标做成竞赛或抽奖活动。
- 试炼热度：参考 `Hades` Heat/Pact 这类可选难度层设计，但 v0.1 只做 H0-H3 本地自选挑战；热度改变敌人生命、伤害和移动速度，并在 HUD、标题页和结算页披露，不绑定付费、不提高 SLOT 概率、不发放每日奖励或排行奖励。
- 本地成就：先以离线 PlayerPrefs 保存成就解锁状态，并在标题页提供成就列表查看；未解锁项要显示本局或最佳记录进度，帮助玩家判断下一局追求速通、启封、极限闪避、连击或高热；不接账号或联网排行，后续如接 Game Center，再把这些本地条件映射到平台成就。
- 可访问性/辅助：辅助模式降低受到伤害并放宽闪避容错，自动朝向降低瞄准压力，自动攻击提供可选 Auto-hit 式触控辅助；三者都通过 PlayerPrefs 保存，恢复默认会关闭自动攻击但保留自动朝向默认开启。
- 低闪烁反馈：设置页必须提供舒适低闪档，降低屏幕闪白峰值/持续时间、震屏强度和受击红边透明度，同时保留必要的危险提示。
- 隐私与披露：标题页和设置页必须能打开关于/隐私说明，明确离线运行、只用 PlayerPrefs 保存本机设置/记录、不接广告/分析/账号/联网排行，以及 SLOT 无真钱付费或现金价值；玩家必须能在游戏内二次确认后清除本机保存数据。
- 移动端设置项：辅助模式、自动朝向、自动攻击、音效开关、震动、总音量/音效/音乐分轨滑杆、总音量快捷档位、特效强度、紧凑按键布局、按钮大小、右手位置、右侧按钮透明度和右侧按钮单键拖动微调都可切换并保存；设置页必须可从标题、HUD 和暂停面板进入，并显示当前档位摘要，让玩家确认辅助操作、按钮大小、右手位置、音频混合和安全区适配状态。控制/反馈偏好需要恢复默认入口，但不能误清玩家记录。
- 可选控制器：参考 Dead Cells mobile 等移动动作游戏的控制器兼容策略，触屏仍是默认主操作，但蓝牙/MFi 手柄应可接入；由于 iOS 系统可能重映射按钮，战斗 UI 不硬显示固定手柄 glyph，只在设置页显示控制器连接状态，并让手柄输入同步屏幕按钮按下反馈。
- 前景可读性：参考移动端动作游戏常见的角色轮廓和实体平台读法，复杂背景上只保留极淡前景可读性带；主角和敌人/Boss 不使用脚底黑影或蓝光环，必须依靠清晰动作帧、类型标记、实体草皮/土层平台和受击短线读清，平台跳跃时才用 `HeroLandingPredictor` 投出预期落点，避免玩家在 iPad 缩放视图里丢失角色或误判落点。
- 危险区可读性：参考移动动作游戏和平台可访问性原则，攻击预警不能只靠颜色；矩形伤害区要加斜纹，圆形雷击区要加十字准星，毒素范围要加波纹线，并配合短文字/倒计时，避免色弱玩家或低亮度环境下误判。
- 攻击预告牌：参考 Dead Cells 等动作游戏可放大的 Attack Announces，Boss/精英/弓手的高危前摇需要有居中 HUD 短预告，写清招式和应对动作；它是世界预警的补充，不替代地面范围和倒计时。
- 命中确认：移动端玩家视线常在角色、敌人和右拇指区之间切换；真实命中必须同时有世界伤害字和靠近右手操作区的短 HUD 确认，轻击/破势/技能/Boss 命中要用文案、颜色、来源标签和力度条分层，空挥不能显示命中确认。
- 冷却/花费可读性：技能、闪避、商店和特殊交互按钮除径向遮罩外，还应提供数字/锁定/差额提示；资源不足时按钮要暗化并说明原因，降低移动端误判。
- 构筑可读性：SLOT/符文类长期增益必须有常驻徽章或图标，并在 HUD 上给当前流派、总构筑等级和最近战术提示；标题页/暂停页需要有符文图鉴，让玩家能随时查看二星、三星、战术用途、概率和无现金价值说明，避免只靠抽取瞬间文字记忆当前打法。
- 抽取仪式感：SLOT 启封必须有三列实体符文盘、滚动减速、二星/三星高亮、奖励说明、打法建议和无共鸣保底提示，确保玩家能看懂“为什么变强”和“哪里改变打法”。
